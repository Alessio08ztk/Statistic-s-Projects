Homework 1: Private Key → Public Key

Elliptic-curve scalar multiplication on a toy curve, Q = kG. Runs entirely in the browser.

The curve is y² = x³ + 7 (mod 17), the same shape as secp256k1 but tiny. A public key is just the private number k multiplied with a base point G: Q = kG. "Multiplying" means adding G to itself k times, using the chord-and-tangent rule.

Discussion


What is actually meaningful for a one-way function on a curve?


    

  • Uniformity – yes, in the sense that the points kG should look spread over the group. Here every point of the subgroup is hit exactly once, which is a perfect "permutation", but also means the map is trivially reversible by a table lookup because the group is small. With 2²⁵⁶ elements the table is impossible.
    • 

  • Hardness – the real security argument is the ECDLP, not any statistical test. A curve can pass every histogram and still be broken (this toy one is).
    • 

  • Structure – note that (a+b)G = aG + bG and that kG and (n−k)G share the same x (they are mirror images). A hash is designed to not have algebraic structure like that, so it's a feature of the curve, not a flaw.
    • 



Hash-specific properties: the avalanche effect (flip one input bit, about half of the output bits change), bit independence and collision resistance are goals of hash functions. In the table above the avalanche numbers come out near "random" only because the space is tiny; on a real curve, k and k+1 give points that differ by one addition of G, which is perfectly predictable if you know the points — you just can't recover k from them. Also, a hash takes arbitrary-length input and has fixed output size, while scalar multiplication does not compress anything.
